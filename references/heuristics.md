# SPEAR 启发式规则手册

> 本手册浓缩性能诊断的启发式规则与领域专家经验，作为 `workflow.md` 分析流程和 `tools.md` 命令参考的补充。

---

## SPEAR 方法论命名

- **S**ystematic - 从资源边界到业务代码的层级化分析
- **P**erformance - 专注高负载、低频采样场景
- **E**mpirical - 工具驱动，无证据不猜测
- **A**nalysis - 多维度关联，结合专家规则库
- **R**eflection - 自我批判机制，对抗确认偏误

---

## 五大认知闭包

### 1. 经验锚定 (Empirical Anchoring)
**原则**: 无工具数据，不进行逻辑推演  
**要求**: 每个假设必须对应一个探测动作

### 2. 竞争性假设 (Competing Hypotheses)
**原则**: 保持"双线思维"  
**示例**: 低效业务逻辑（主动）vs 调度/资源压制（被动）

### 3. 搜索空间收敛 (Search Space Convergence)
**原则**: 漏斗模型 - 先定天花板，再找主干道，最后定位局部

### 4. 因果交叉验证 (Causal Cross-Validation)
**原则**: 证据必须形成链条  
**示例**: 业务层锁竞争必须与系统层调度延迟相关联

### 5. 证伪优先 (Falsification)
**原则**: 最终结论前审计证据链  
**问题**: "问题解决了吗？还有其他可能性吗？"

## 领域诊断规则

### 进程级诊断标准

| 规则 | 描述 | 优先级 |
|------|------|--------|
| 资源边界压制 | 优先分析 Cgroup 规格和限流指标 | **#1** |
| 全路径审计 | 使用 inclusive 统计确保稳定，忽略单点噪声 | 高 |
| 基础库聚合 | 识别公共工具函数（memcpy, malloc）- 指示数据处理模式问题 | 中 |
| 用户空间同步损耗 | 监控同步原语比例以发现锁竞争 | 中 |
| 进程生命周期异常 | 高 PID 多样性 + 低单 PID 样本数 = 进程风暴 | 高 |

### 系统级诊断标准

| 规则 | 描述 | 指标 |
|------|------|------|
| 中断与调度延迟 | 内核长临界区 | `spin_unlock_irqrestore` 模式 |
| 内核全局聚合 | 跨进程内核开销聚合 | 所有参与者均受影响 |
| 调度器效率 | 调度器内部函数开销 | >10% 表示系统过载 |
| 架构与内存瓶颈 | 内存直接回收和 TLB 同步 | 微突发抖动检测 |

## 工具使用铁律

1. **工具强制**: 禁止"裸猜测"。每次分析必须以"根据工具检测结果..."开始
2. **范围严谨**: 禁止从阶段 1 跳到阶段 4。严格遵循环境→代码路径
3. **可靠性阈值**: 19Hz 采样时验证样本总数，低于置信阈值标记为"推测"
4. **证伪优先**: 优先收集排除搜索域的证据，而非支持假设的证据
